# 错标检查、漏标补充与换装检查

[返回功能导航](../feature-map.yaml)

核对日期：2026-11-28。覆盖顶栏入口、左侧导航、检查设置、后台检查、本地观察、数据集参考图、人工应用、忽略和批次撤销。打标或导入 TXT 后都可使用。

## 入口和实现

- [Header](../../app/src/App/__internal__/Header/Header.tsx)：顶栏“标签检查”入口，与“标签编辑”并列，打开数据集后可用。
- [TagAuditPage](../../app/src/Pages/TagAuditPage/TagAuditPage.tsx) 通过与数据集工具共用的 [SideTabLayout](../../app/src/components/SideTabLayout/SideTabLayout.tsx)，提供“错标检查”“漏标补充”“换装检查”和“检查设置”四个子页。漏标和换装共用参考图选择弹窗。三种检查共用图片预览、状态筛选、单项或批量处理及应用历史与撤销。
- [AuditSettings](../../app/src/Pages/TagAuditPage/__internal__/AuditSettings/AuditSettings.tsx) 提供共用的 API 地址、模型 ID、并发数、禁用标签和错标视觉开关。`TagAuditPage` 按当前数据集维护同一份配置草稿，往返设置时保留当前检查的操作状态。
- [tag_audit.py](../../core/dataset_pipeline/tag_audit.py) 复用本地服务请求与图像预处理。`audit_run` 并发观察，后台任务线程逐样本合并和保存。漏标按特征 ID 保存最近一轮，错标和换装各自保存最近一轮，共用建议与批次处理。
- [feature_audit.py](../../core/dataset_pipeline/feature_audit.py) 管理特征定义、参考图版本、禁用标签冲突及特征观察协议。
- [costume_audit.py](../../core/dataset_pipeline/costume_audit.py) 管理标准服装参考图版本、描述和双图逐部位比较协议，并按可见性和差异类型得出结论。
- [AuditSampleActions](../../app/src/Pages/TagAuditPage/__internal__/AuditSampleActions/AuditSampleActions.tsx) 提供错标检查中失败和不确定条目的单张标签编辑与重试。手工保存走现有单图标签写入协议。
- [server.py](../../webui/server.py) 通过 `start_audit` 启动错标或顺序运行所选特征，通过 `start_costume_audit` 启动换装检查。`retry_audit_samples` 支持错标的失败及不确定样本，以及指定漏标或换装轮次的失败样本。兼容旧 `retry_audit_failed` 请求。`apply_audit`、`ignore_audit`、`undo_audit` 和特征编辑与后台任务互斥。`/api/tag-audit/feature` 保存定义及所选样本，`/image` 提供训练图预览，`/api/state` 检查参考图及结果是否有效。

## 检查协议和范围

范围固定为当前数据集活跃、已接受且标签有效的样本，不随标签页筛选与勾选变化。直接读取 `tag.image` 对应训练样本，EXIF 校正并转换 RGB，等比例限制长边至 1536 后发送。使用用户配置的本机 HTTP `/chat/completions` 兼容接口，不跟随重定向，不使用环境代理，不启动 Forge。地址应包含服务需要的 `/v1` 前缀；默认填入本机 `http://localhost:23333/v1` 和 `qwen3.5-4b-uncensored-hauhaucs-aggressive`，可在页面修改，随检查保存到数据集。并发请求数 `concurrency` 通过横向滑杆在 1–16 间调整，默认 1，历史配置缺少该字段时仍使用 1。视觉请求通过线程池限制同时执行数量；每份样本完成后由后台任务线程合并结果、保存记录并更新完成数，单份失败不终止其他样本，失败样本仍保留禁用标签规则结果。关闭视觉检查时只顺序执行规则，不发送模型请求。

视觉模型设置可调整最大输出 token 数和采样参数。缺少字段时使用项目默认值：`max_tokens: 8192`、`temperature: 0`、`top_k: 20`、`repeat_penalty: 1`、`presence_penalty: 1.5`、`top_p: 0.95`、`min_p: 0`。项目逐请求发送这些值，已有数据集保存的自定义值优先。输出上限留空时使用 8192，采样参数留空时不随请求发送，使用模型服务默认值。模型启用思考时，思考与最终答复共用输出预算。参数随检查保存到数据集，并记入该轮次的执行配置。

检查设置中独立的“Forge 模型”分组提供“卸载 Forge 生图模型”按钮，通过 `POST /api/forge/unload-checkpoint` 连接全局设置中的 Forge。项目有后台任务或 Forge 正在处理任务时拒绝卸载。空闲时由 [ForgeClient](../../core/dataset_pipeline/forge.py) 调用 Forge 的 `/sdapi/v1/unload-checkpoint`，为视觉检查腾出显存和内存。按钮只连接已经运行的 Forge，不启动服务。下次生图时 Forge 会重新加载模型。

全量检查通过启动校验后，服务端先清除即将执行的检查上一轮失败记录。漏标按当前执行的特征更新失败记录。`tag_audit.executions` 为每轮检查和每次重试保存实际配置及观察协议版本，样本和建议通过 `executionId` 关联对应记录。旧轮次读取时保留原结果，可随之后的检查记录写入迁移后的格式。

错标检查将训练图与固定观察问题传给模型，返回人数、可判定的男女人数、构图范围、确定性与简短视觉依据。程序核对人数标签、`solo`、`no humans` 及有限的构图冲突；这类检查生成删除建议。

身份和来源类使用用户明确填写的当前数据集禁用标签，按规范化后的完整标签匹配。禁用列表默认空，可关闭异常检查中的视觉观察，只执行规则。视觉服务失败时仍保存本图规则结果。

错标检查的“不确定”和“失败”样本都在主清单，支持通过状态下拉框或计数按钮筛选。每条记录显示训练图、模型依据或失败原因以及当前工作标签。可以预览图片，按需要编辑和保存此图标签。人工编辑更新工作 TXT，模型观察记录会保留。

可重试单项，或筛选后重试该状态下的全部有效样本。漏标和换装也支持重试单个失败样本或当前轮次的全部失败样本。重试使用当前填写的模型、地址和并发数，沿用已保存的禁用规则和原轮次的特征定义或标准服装参考。重试只替换目标样本的观察记录，按新状态移动条目，其他样本的结果继续保留。重试过程保留工作 TXT。进度区显示任务进度和完成状态，整轮任务中断时报告任务级错误。

错标检查、漏标补充和换装检查的“不确定”“失败”“已过期”及“待处理”或“待补标”筛选支持从操作行右侧清空。确认后，`clear_audit_results` 校验当前数据集并清除当前检查符合筛选条件的所有分页记录。错标检查的建议还受类型筛选约束。漏标和换装校验当前轮次 ID，按主清单显示的有效状态移除对应观察及其关联的补标建议。清空只写入检查记录，已应用批次的撤销依据保留在批次历史中。

## 漏标补充

数据集可保存多条特征。新增或编辑时，在双栏弹窗左侧选择一张已接受且标签有效的训练图。在右侧查看图片，并从工作标签中勾选一个或多个目标标签。换图会清空已选标签。确认后填写名称和可观察描述，说明标签组合指向的视觉特征。现有单标签定义可照常打开和使用。

一次可勾选多个特征，后台按顺序执行单特征任务并累计进度。每个请求发送一个特征的名称、可观察描述和一张目标训练图。模型判断描述中各项是否共同出现，并返回 `present`、`absent`、`unobservable` 或 `uncertain` 和简短依据。参考图及其版本用于选取和校验目标标签，保存在应用内。模型服务拒答、截断或返回无效结果时，该样本进入失败状态。

“查看特征”切换当前显示的结果。`tag_audit.featureRuns[featureId]` 保存各特征最近一轮，旧的单个 `featureRun` 按其中的特征 ID 迁移。重跑只更新所选特征的轮次及其待处理队列。

确认整个特征存在且缺少目标标签时才生成补标建议，每张图只建议添加缺失的标签。已一致、未发现、不可观察、不确定和失败可在状态筛选中查看。组合中任一目标标签命中禁用列表时，需要调整规则或目标标签再检查。

## 换装检查

从当前数据集选一张标准服装参考图。可直接填写标准服装描述，也可通过 `describe_costume` 让视觉模型只看参考图并生成上衣、外套、下装和鞋袜的描述草稿。核对、编辑后点击“确认描述并运行换装检查”。检查覆盖全部有效样本，参考图自身计作标准服装，每张其他图与参考图、确认过的服装描述一同发给视觉模型。

模型逐部位给出两图的可见性、可见衣物和差异类型。程序仅在相同部位两图均清楚可见且主衣物类型或结构有明确差异时生成换装候选。缺少共同可见部位时归入不可观察。只有色差、配饰或动作等弱证据时列为不确定。确认描述、参考图版本和样本结果保存在 `tag_audit.costumeRun`，实际执行双图观察的样本还保存通过校验的 `regions`。旧双图协议生成的待补标和已忽略建议视为过期，其应用批次仍可撤销。

左侧默认筛选“识别为换装”，同时呈现待补标和已标注的换装图。缺少 `alternate costume` 时生成补标建议，可单张或勾选后批量确认。状态筛选可查看标准服装、不可观察、不确定及失败。参考图变化后，待处理建议会过期，可重新选择参考图并运行检查。

## 人工决定与写入

运行检查不修改工作 TXT。操作行可选择本页待处理项，或跨分页选择当前状态和类型筛选范围内的全部待处理项。单项和批量补标均在应用内弹窗确认，弹窗显示所选建议数量、目标标签及撤销方式。确认后将缺少的目标标签追加在现有标签后，作为人工标签进入导出。历史建议缺少动作字段时按删除处理。单项应用也作为一个批次。

特征定义、参考图、图像版本（标签键、路径、裁框、文件尺寸和修改时间）或相关类别标签变化时，待处理和已忽略结果会过期。参考样本失效、图片变化或所选标签被移除时，需要重新确认参考图和标签。手动补上目标标签后，旧建议无法再应用。图片、相关标签和特征版本一致时，重跑保留忽略决定。此前使用参考图参与推理的待处理结果会过期，原定义可直接重新检查。应用批次仍可从历史撤销。

每个应用批次保存样本前后标签及图像版本。撤销要求图片和当前标签仍与该批次应用后快照一致；有后续编辑时拒绝覆盖，可以先撤销后续批次。写入异常会尝试恢复受影响 TXT 与记录；不承诺跨文件的断电事务。导入来源图片和 TXT 不写入。
